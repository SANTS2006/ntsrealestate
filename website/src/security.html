Five layers between your data and the wrong hands

Each layer assumes the one above it could fail. Scroll and watch them separate.

{{i:lock}}

Strong authentication

Passwords hashed with Argon2id. Optional multi-factor authentication with recovery codes, and MFA secrets encrypted with AES-256-GCM.

{{i:users}}

Hybrid sessions

HttpOnly, Secure, SameSite cookies backed by Postgres for the web app; short-lived JWTs with rotation for mobile and API clients.

{{i:shield}}

Role-based authorisation

Permissions follow a clear resource:action model, with resource-level checks so users only reach records assigned to them.

{{i:database}}

Organisation isolation

Every organisation's data is separated. Our tests probe cross-organisation access on each core resource type.

{{i:cloud}}

Private documents

Uploads are validated by file signature, names are sanitised and sensitive files are never publicly reachable.

{{i:eye}}

Audit trail

Important actions are logged so you can review who did what — and the platform has its own separate audit log.

{{i:layers}}

Hardened API

Strict CORS allow-list, Helmet security headers, double-submit CSRF protection, validated inputs and rate limiting — tighter on sign-in routes.

{{i:wallet}}

Financial integrity

Idempotent payments, over-payment rejection, clean refund reversal and void protection keep the books honest.

{{i:database}}

Backups & recovery

Platform-level backup and restore tooling, with documented recovery and reliability procedures.
